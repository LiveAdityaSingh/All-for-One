All-for-One Data Model

Every record the five agents write lives on the device, in one IndexedDB database named all-for-one, managed through Dexie. There is no server copy and no account: the database is scoped to the browser origin, so a second browser or a second phone starts empty.

What makes a future sync possible

Nothing syncs today, but the scaffolding for it is already in every write. Two Dexie hooks stamp modifiedAt on create and on update across all eight synced tables, so no call site can forget the way a manual assignment can. A no-op update is left alone, so it does not look like a change to a peer that isn't there yet.

Eight tables carry that stamp and travel in a backup: applications, cvVariants, claims, captures, tasks, accounts, balanceSnapshots and transactions. settings is excluded by design and deletions is the tombstone log itself.

Only three tables index modifiedAt — applications, transactions and tasks — because those are the ones an export walks most often. The rest carry the field without the index, which costs nothing on write.

How the schema got here

Six versions. Two of them moved existing records rather than only adding stores.

v1

applications, cvVariants, claims

Tony first: the agent the whole app was built to serve.

v2

captures

A single landing pad, so voice could work before any agent had a screen of its own.

v3

tasks moved data

Every capture with kind: "event" became a real task and was deleted from captures, so nothing you had already spoken silently vanished when Lisa got a surface.

v4

accounts, balanceSnapshots

The balance loop, and the history runway needs.

v5

transactions, settings moved data

Same again for money: captures with kind: "expense" became transactions rather than being stranded in a list nothing read.

v6

deletions, plus modifiedAt indexes

Tombstones and change stamps. Added before there was a sync to use them, because backfilling months of records later is far more expensive than stamping them now.
